# 财税领域包（caishui）

> 本文件是 data-desk 的财税领域包：面向会计、出纳、税务专员、财务分析与审计助理。
> 基础用法见 SKILL.md；本文只讲财税人的专业场景。命中财税模式后按需使用本文各节。

## 这是什么 / 能帮我做什么 / 怎么开始

- **这是什么**：把你手上的 Excel（科目余额表、银行流水、发票明细……）变成"随时能问的账"。你还是说人话，但回答会按财税惯例来——借贷方向、红冲抵减、期间对比，都按行规处理。
- **能做什么**：问数（"管理费用这个月多少"）、对账（"对一下银行流水"）、核对（"进销项发票核对"）、对比（"余额表这个月比上月"），结果一句话导出 Excel 底稿。
- **怎么开始**：把文件丢过来说一句行话即可，例如"帮我对一下银行流水"。第一次用请先看下面三个配方，每个都有"你说了什么 → 你会得到什么"。

## 领域术语表

| 术语 | 含义 | 在本技能中的处理 |
|------|------|------------------|
| 借方 / 贷方 | 复式记账的两个方向 | 作为普通列参与计算；方向性判断由配方按科目性质决定 |
| 期间 / 账期 | 会计所属月份（如 2026-09） | 分组维度，必含年份，防跨年同月混组 |
| 红冲 / 红字 | 负向冲销（发票或分录） | 负数参与合计，抵减不叠加；括号"(300)"视为 -300 |
| 未达账项 | 一方已记、另一方未记的账 | 对账配方输出的核心清单 |
| 价税合计 | 不含税金额 + 税额 | 发票核对时做一致性校验（偏差即异常） |
| 试算平衡 | 期末 = 期初 + 借方发生 − 贷方发生 | 余额表配方的自动校验，不平科目单独提示 |
| 账龄 | 应收款拖欠时间分档 | 下期配方（暂未收录） |
| 权责发生制 | 收入费用按归属期确认 | 解释期间对比口径时使用 |

## 通用清洗片段（金额与日期）

**先读后算**：金额/日期列凡含文本痕迹，一律先清洗再计算。全部用 `try_cast`/`try_strptime`，坏值落 NULL——**NULL 行必须单独列出并提示，不许静默丢弃**。

```sql
-- 金额：去千分位、去货币符号（¥ ￥ ，）
try_cast(replace(replace(replace(金额, ',', ''), '¥', ''), '￥', '') AS DECIMAL(18,2))

-- 金额：括号红字负数，"(300.00)" → -300.00
CASE WHEN trim(金额) LIKE '(%)'
     THEN -try_cast(translate(金额, '()', '') AS DECIMAL(18,2))
     ELSE  try_cast(replace(金额, ',', '') AS DECIMAL(18,2)) END

-- 日期：三种常见格式混排，统一为 DATE（可按需追加格式）
coalesce(try_cast(日期 AS DATE),
         try_strptime(日期, ['%Y/%m/%d', '%Y-%m-%d', '%d-%b-%Y'])::DATE)
```

- **"万元"等数量级单位列**：属于业务语义，脚本猜不了——**必须先向用户确认单位再 ×10000**，禁止自作主张换算
- Excel 类型规律（read_xlsx）：日期列若原表设了"日期格式"会被直接识别为 DATE；识别不可靠时加 `all_varchar = true` 全文本读入后用上面片段清洗

## 通用问答规范（财税模式下的问数）

财税模式下回答任何问数问题，按此流程：

1. **先探后答**：`SHOW TABLES` → 对相关表 `DESCRIBE` / `SUMMARIZE`，弄清列与规模再作答
2. **列名模糊对应**：用户说"借方金额"而表里是"借方发生额"，直接对应作答；找不到明显对应时，列出最接近的候选列名请用户确认，不猜
3. **结论先行**：答案必须含结论句——发生了什么 / 关键差异或异常数值 / 建议下一步看什么，不许只甩一张裸数据表
4. **金额先清洗**：涉及金额列先过"通用清洗片段"，再聚合
5. **规模保护**：目标表 >100 万行先建议加 LIMIT 或聚合（SKILL.md 既有规则）

**示例（你说了什么 → 你会得到什么）**：

- "管理费用这个月比上月多了多少？" → "多 15,000.00 元（80,000 → 95,000，环比 +18.75%），全部来自本期新增发生额。建议按明细科目再拆一层看增量来源。"
- "各费用科目合计多少？" → 一张按科目汇总的表 + 结论句"共 3 个费用科目，合计 xx 元，占比最高的是 xx"。

## 配方六段式模板

本文每个配方固定六段，缺一不可：

1. **适用数据**：期望字段清单（缺列时如何引导用户对应）
2. **触发话术**：≥3 条"用户说"示例
3. **前置检查**：动数之前的核对动作（列是否存在、行数规模）
4. **步骤**：SQL 惯用法序列（FROM-first、GROUP BY ALL、引用上方清洗片段）
5. **结果解读**：必含结论句式——发生了什么 / 关键差异或异常 / 建议下一步
6. **常见坑**：该场景最容易算错的地方

输出统一契约：结论句 + 业务词汇列头的结果表 + 数据质量提示（清洗失败行）+ 可选一句话导出 Excel（同名文件先确认）。

## 配方 duizhang：银行流水对账

1. **适用数据**：流水表与账面记录（可各一个文件/sheet）。期望字段：交易日期、金额、摘要/对方户名；账面侧最好有凭证号。缺列时请用户指认对应列。
2. **触发话术**："帮我对一下银行流水""银行流水和账上对一下""找一下未达账""这个月流水核一下"。
3. **前置检查**：确认两张表的金额列、日期列已过清洗片段；报一下两侧行数；金额单位是否一致（元/万元）必须先确认。
4. **步骤**：金额、日期先清洗 → 按匹配键 FULL OUTER JOIN：日期相等（或 ±容差窗口内）且金额精确相等 → 已核对；单侧存在 → 未达项。多对一时按"金额+日期+顺序"贪心配对并在结果中标注。
5. **结果解读**：结论句式 + 未达项清单（仅流水/仅账面）+ 差异金额合计。示例："共 30 笔，已核对 27 笔；3 笔未达（流水已记账面未记 2 笔共 1,500 元，账面已记流水未记 1 笔 300 元），建议先查 9 月 5 日手续费 88.5 元是否漏记。"
6. **常见坑**：金额一正一负方向相反（流水收支标志 vs 正负号，先统一为带符号金额再比）；手续费/利息小额易漏；同期多笔同金额要靠顺序配对，不可简单去重。

```sql
-- 匹配键示意（金额列已清洗、日期已统一为 DATE）
FROM 流水 f FULL OUTER JOIN 账面 v
  ON f.金额 = v.金额 AND abs(f.交易日期 - v.交易日期) <= 3
SELECT f.交易日期, f.金额, v.凭证号,
       CASE WHEN f.金额 IS NULL THEN '仅账面'
            WHEN v.金额 IS NULL THEN '仅流水'
            ELSE '双方一致' END AS 匹配状态
```

## 配方 fapiao：进销项发票核对

1. **适用数据**：进项、销项发票明细各一张表。期望字段：发票号码、开票日期、金额（不含税）、税额、价税合计；最好有购/销方名称与状态（正常/红冲）。
2. **触发话术**："核对一下进销项发票""进销项对一下""发票匹配检查""票表核对"。
3. **前置检查**：发票号码去空格后比对；确认无税金额与税额列的口径；红冲以负数金额或状态字段两种形态存在，先问用户是哪种。
4. **步骤**：号码标准化 → 按号码 FULL OUTER JOIN → 匹配状态（双方一致/仅进项/仅销项/重复）→ 校验 金额+税额=价税合计，偏差行进异常清单 → 红冲按负向抵减参与合计。
5. **结果解读**：示例："共 58 张，一致 55 张；重复号码 1 张、仅进项 1 张；2 张价税合计对不上（差 0.01，疑似四舍五入），建议按开票日期回查原票。"
6. **常见坑**：全角/半角与前后空格导致"号码对不上"的假异常；红冲票重复计入会成倍虚增；四舍五入造成 1 分钱偏差不算异常，设容差。

## 配方 duibi：科目余额表多期对比

1. **适用数据**：科目余额表。期望字段：科目编码、科目名称、期间（含年月）、期初余额、借方发生额、贷方发生额、期末余额、余额方向。
2. **触发话术**："余额表两个期对比一下""这个月比上月变动""科目变动分析""对比 8 月 9 月余额表"。
3. **前置检查**：期间维度必含年份（2026-09 不能只写 09）；科目编码唯一；金额列过清洗。
4. **步骤**：试算校验（期末 = 期初 + 借方发生 − 贷方发生，借方科目；不平单独提示）→ 按科目 PIVOT 出各期数值 → 变动额/变动率 → 按绝对变动额排序标注最大项。
5. **结果解读**：示例："6602 管理费用期末较上月增加 95,000 元（+54%），为本期最大变动项，主要来自借方发生额增加 15,000 与期初结转；建议下钻明细账。"
6. **常见坑**：借/贷两种方向的科目直接用期末余额相减会算反方向（先按余额方向统一符号）；跨年期间必须带年份分组；新增科目（上期为 NULL）按 0 处理并标注"新增"。

```sql
-- 变动额示意（PIVOT 出两期期末后）
SELECT 科目编码, 科目名称, "2026-09" AS 本期, "2026-08" AS 上期,
       "2026-09" - coalesce("2026-08", 0) AS 变动额
FROM (FROM 余额表 PIVOT sum(期末余额) FOR 期间 IN ('2026-08', '2026-09'))
ORDER BY abs(变动额) DESC
```

## 导出

- 单次结果导出：`COPY (SELECT ...) TO '未达项清单.xlsx' (FORMAT xlsx, HEADER true);`
- 整表导出：`COPY db.t_name TO 'out.xlsx' (FORMAT xlsx, HEADER true);`
- **必须带 `HEADER true`**——实测 `COPY TO xlsx` 默认不写表头，读回来列名会变成第一行数据
- 同名文件已存在时，先问用户覆盖还是另存，禁止静默覆盖
- 老规矩：输入与输出不得是同一个文件
- 导出后报一下行数与文件路径，方便用户归档底稿

## 脏文件适配（真实世界的 Excel）

财务 Excel 很少规整。以下参数已按 DuckDB 官方文档（lts）核实，按场景取用：

| 现象 | 解法 |
|------|------|
| 表头上方有标题行/空行 | `read_xlsx('f.xlsx', range = 'A3:G', header = true, stop_at_empty = true)`（从第 3 行开始读；**列范围收到实际数据列如 G，且必须加 `stop_at_empty = true`，否则会一路读到工作表末尾产生百万空行**——实测踩坑） |
| 只要某个 sheet | `read_xlsx('f.xlsx', sheet = '9月', header = true)`（默认第一个 sheet） |
| 多 sheet 合并 | 每个 sheet 一个 `read_xlsx(...)`，`UNION ALL BY NAME` 拼接，并报各自行数 |
| 类型识别不可靠 | `all_varchar = true` 全文本读入 + 通用清洗片段显式转换 |
| 日期被读成文本 | 上方清洗片段的 `coalesce + try_strptime` |
| 空 cells 变 NULL 干扰 | `empty_as_varchar = true` |

- `read_xlsx` 会依据单元格"数字格式"推断 DATE/TIMESTAMP；不可靠时一律 `all_varchar` + 显式清洗
- **合并单元格**：被合并区域只有左上格有值，读出为空——关键列大面积空值时提示用户该表存在合并单元格，建议取消合并或指定 `range` 后再处理，不静默补值
- **失败话术**（读不了时一次性说清，不许只甩报错）："这份表第 1–2 行是标题和空行，数据从第 3 行开始。我可以从第 3 行开始读，或你删掉前两行再给我，哪种都行。"
